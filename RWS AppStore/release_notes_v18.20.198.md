## Changelog

### Added
- **An AI assistant writing through the MCP server can now update your translation memory as it goes.** `update_segments` has a new option, `updateTm`. With it, each segment the assistant leaves Translated, Approved or Signed off is also written to the project's main translation memories, exactly as when you confirm a segment yourself: rewriting a segment updates the unit it wrote before rather than adding a second one, and translations stored for the same sentence in other places are left alone. Drafts are never sent, so nothing reaches the memory unreviewed, and the option is off unless the assistant is asked to use it. Each segment's result says whether the memory took it. Save the document afterwards: the link between each segment and its unit in the memory is kept there.
- **A large memory bank now sends only what each document needs.** When your memory bank and `_shared` together come to more than about 8,000 tokens, Batch Translate, Translate active segment (Alt+T), Preview prompt and SuperBench sent all of it with every request, up to 24,000 tokens, however little of it the document could use. The first time you translate a document, Supervertaler now keeps only the terminology rows whose terms occur in it (in either column, so a Dutch-English table still serves an English-Dutch job), and asks your AI model once which of the bank's other notes matter for it; the bank's own brief and style guide always go. Your house defaults in `_shared` are judged rule by rule in the same question: each `## ` section of `_shared/style.md`, and each section of `_shared/terminology.md` without a table, is offered on its own, so a rule written for another language direction or kind of document (nl→en patent boilerplate on an en→nl software job, say) stays out. A **Scope:** line at the top of a rule is what the model goes by. The result is kept for that document until you change the bank, so every request carries the same text and the provider's prompt cache keeps working. Nothing goes to the model when you merely open a document. The question is one small request per document, listed in the Reports tab under SuperMemory, and if it fails or times out every note is sent as before. What was sent, what was left out and why is written to the `trados\bank-extracts` folder in your Supervertaler data folder, and the Batch Translate log points to it. A bank of 8,000 tokens or less is sent whole, exactly as before.
- **Notes in a memory bank can be marked for the AI assistants only.** A note whose frontmatter says `audience: assistant` (working notes such as how to check a termbase before a batch) is now left out of Batch Translate, Translate active segment, Preview prompt, SuperBench and AutoPrompt, and the Batch Translate log names what was left out. The AI Assistant chat and AI tools connected through the MCP server still read it: they are who it is written for. A note without the marker is sent as before.
- **AI translations are now checked before they reach your document.** A model would sometimes add something to a translation that was not part of it: a note explaining a choice, a remark about the translation memory match, markdown formatting. Batch Translate and Translate active segment (Alt+T) wrote that straight into the target. Every translation request now ends with a fixed set of output rules that no prompt can switch off (Preview prompt shows them), and every reply is checked against them before it is written. A reply that breaks them is asked for once more, with the rules repeated; if the second answer breaks them too, the segment is left empty and the Batch Translate log names it and says why. An empty segment costs you one segment; a note in the target could reach your client. Paste from Clipboard cannot ask again, so it leaves such a segment out and names it in the log. The rules give the AI one place for a remark that matters: a single `[[TC: …]]` marker at the end of the segment, 5 to 20 words written as your comment to the client, for a defect in the source, a real ambiguity, an error it corrected in a 100% TM match, or a deliberate departure from the termbase. Supervertaler for memoQ applies the same rules.
- **The Reports tab shows what your AI calls are costing, as you work.** A line under its header reads, for example, "AI cost: $1.23 this session (since 09:14) · $4.56 today". It counts every AI call Supervertaler makes in Trados (Batch Translate and Proofread, Translate active segment, the AI Assistant chat, QuickLauncher, AutoPrompt, the memory bank selection), whether or not prompt logging is on, and updates as each call finishes. Today's figure comes from the usage log, so it includes earlier sessions today and the other Studio version if you run both. A model without a price is counted at the most it can have cost, marked "up to". Until now, cost showed only per call (with prompt logging on) or in the monthly Usage & Costs report, so a day of expensive calls could go unnoticed until the bill.
- **Two new voice commands: "SuperSearch" and "web search".** Select a word or phrase and say **"SuperSearch"** to search the project's files for it (Alt+S), or **"web search"** (or "search the web") to open it in your enabled SuperSearch web resources (Alt+W). If you have customised your voice commands, the two are added to your list automatically. The About box now lists Alt+S and Alt+W with the other shortcuts.
- **Choose where the AI's `[[TC: …]]` comments go.** By default they stay at the end of the target, where you see them while you review: remove them before you confirm the segment, or turn them into comments yourself. Tick **Add the AI's [[TC: …]] notes as Trados comments** in Settings → AI Settings to have each one taken out of the target and added to the segment as a Trados comment instead.

### Changed
- **Translation memory matches are now offered to the AI as a reference to check, not as wording to follow.** Batch Translate (and, from this version, Copy to Clipboard) told the AI that every TM match had been written and approved by a human, that it should follow them, and that a 100% match should be reused as it stands. A memory often holds translations made for other documents, products or clients, and they can be wrong, even at 100%: a 100% match means only that the source sentence is the same. The matches now go to the AI as earlier translations to check against the segment and the document. It reuses a match's wording only where it is correct for that segment, the termbase and the document take precedence, and where a match does not fit, or it is in doubt, it translates from the source. A correct match is still reused. The `[[TC: …]]` note is now asked for when the AI corrects an error in a 100% match, rather than for any departure from a match: departing from a fuzzy match is routine, and a note on every one would bury the notes that matter. Preview prompt shows the new wording.
- **A model that is not in the price list now shows the most it can have cost, instead of "unknown".** For a model Supervertaler has no price for, such as one on a custom OpenAI-compatible endpoint or an OpenRouter model outside the built-in list, the Reports tab and the cost line in the AI Assistant said "unknown", SuperBench showed no cost, and SuperBench's estimate before a run counted that model as costing nothing. They now show "up to $X": the tokens used, priced at the dearest rates in the list (currently $10 per million input tokens and $50 per million output). A model dearer than that is the one case the figure can understate, so add its real rate to `pricing.json` if you use one. Ollama models still show as free. The usage log keeps its `cost_known` field, so an exported report still says which figures are real.
- **Claude Sonnet 5.5 replaces Sonnet 5 as the default Claude model.** It is Anthropic's newest Sonnet, released on 28 September 2026, at the same price as Sonnet 5 ($2 / $10 per million tokens). The Claude list in AI Settings now holds the newest model of each kind: Sonnet 5.5, Opus 5.5 and Fable 5.1. If you have Sonnet 5 or Haiku 4.5 selected, nothing changes for you: it appears in the custom model ID field, keeps working and is still costed.
- **The OpenRouter list in AI Settings offers the same current models as the direct providers.** Claude Sonnet 5.5, Opus 5.5 and Fable 5.1, GPT-5.6 Sol, Terra and Luna, and Gemini 3.8 Flash take the place of Claude Sonnet 5 and Opus 5, GPT-5.5 and Gemini 3 Flash; GPT-5.4 Mini, Gemini 3.1 Pro, Gemma 4, Mistral Small 4 and DeepSeek V4 stay. Sonnet 5.5 is the new default. If you have one of the older models selected, nothing changes for you: it appears in the custom model ID field and keeps working. The OpenRouter prices in `pricing.json` are brought up to date too: Gemini 3.1 Pro, Gemini 3 Flash and GPT-5.4 Mini were costed below what OpenRouter charges, and the new models and DeepSeek V4 had no price, so their cost showed as "up to".
- **The Default Translation Prompt no longer invites notes.** It told the AI it could "add a brief explanation in parentheses" when a term had no established equivalent, which a model can take as licence to explain itself in the target. It now asks for a `[[TC: …]]` marker instead. Your copy is updated automatically unless you have edited it; an edited copy is left alone.
- **Batch Proofread answers in one fixed format, and writes source queries for your client.** The format a proofreading reply must follow is now stated once, at the end of the instructions, where a custom proofreading prompt cannot change it by accident. When the proofreader finds an error in the source rather than in the translation, it writes the Issue line as your comment to the client, 5 to 20 words stating the problem and the fix, so you can pass it on as it stands.
- **En dashes instead of em dashes throughout the plugin.** Window titles, messages, labels, tooltips, the Batch Translate and re-import logs, and the files exported for review used the long em dash (—), which is American typesetting. They now use the spaced en dash (–) of British house style, as the documentation already does. The text Supervertaler sends to the AI is changed in the same way, including the proofreading checklist, the Clipboard Mode instructions and the lines listing TM matches, so the instructions no longer show the AI a punctuation mark your translation should not have. An em dash in your documents is still recognised wherever it was before; the AutoTagger, for one, still treats it as a hyphen.

### Fixed
- **Copy to Clipboard now sends your translation memory matches too.** Since 18/19.20.190, Batch Translate has searched the project's translation memories and sent each segment's closest approved translation to the AI, together with the source it was made for. Clipboard Mode never did. The **Send TM matches to the AI** checkbox was shown there, ticked, but every segment was copied as it stood, so an empty segment always went out as `[new]` with nothing from the memory, unless you had opened it in the editor first and let Trados insert the match. Copy to Clipboard now runs the same search and puts the matches ahead of the segments, in the same words ▶ Translate sends them: the memory's source, its translation and the percentage, for every segment with a match at or above **Lowest TM match to send** in AI Settings. The segments below them, and how Paste from Clipboard reads the reply, are unchanged. The search runs in the background with the progress bar moving, so Trados stays responsive on a long document. Preview prompt in Clipboard Mode shows the matches too, and no longer says the prompt is split into several requests: Clipboard Mode copies the whole scope at once. Copy to Clipboard also now waits for a running Paste from Clipboard to finish, because copying while a paste was still writing could send the rest of it to the wrong segments.
- **A project opened for the first time could lose its database.** Since 18/19.20.192, when you opened a project whose name matches one of your memory banks for the first time (a new project, or one renamed in Trados, which Supervertaler sees as new), the bank could be recorded before the project's settings had been set up. The project then opened with no database: Settings → Termbases said "No database selected", TermLens showed no terms, and no termbase terms went to the AI. Whether it happened depended on which part of Supervertaler Trados told about the project first, so it did not happen every time. A new project now always starts from the same settings, whichever part sets it up: your current database, with every termbase switched off until you tick it for that project. A project settings file that cannot be read is no longer replaced: it is kept beside the new one, with ".unreadable-" and the date added to its name. If a project of yours opened without its database, choose the database again in Settings → Termbases (Browse…) and tick that project's termbases again.
- **Renaming a project in Trados no longer resets its Supervertaler settings.** Supervertaler keeps each project's settings (which termbases are on, the write and project termbases, the memory bank, the prompts, the drawings folder) under the location of the project file, and renaming a project in Trados renames that file, so a renamed project opened as if it were new, with every termbase switched off. Supervertaler now also records Trados's own identifier for each project, which a rename does not change, and a renamed or moved project keeps its settings. This works for a project that has been opened at least once with this version before it is renamed. A copy of a project still starts with fresh settings, and the original keeps its own.
- **Translating one segment at a time costs far less.** Each Translate active segment request (Alt+T) sent the same instructions, SuperMemory context and document content as the one before, but with the current segment's termbase terms placed among them, so the provider saw a new prompt every time. On Claude that meant paying 25% extra to store the prompt for reuse and then never reusing it. The segment's terms now travel with the segment, the rest of the prompt is identical from one segment to the next, and from the second segment on it is read back at a tenth of the input price, as long as each segment follows the last within five minutes. With a 40,000-token prompt on Claude Opus 5.5, that is about $0.20 for the first segment and under $0.02 for each one after it, where every segment used to cost $0.20. OpenAI, Gemini and DeepSeek, which reuse a matching prompt opening automatically, now match the whole of it. Batch Translate runs of several segments are unchanged. The Reports tab now also shows what a one-batch run sent besides its system prompt, and the prompt log files record how many input tokens were read from and written to the cache.
- **If Alt+T (Translate active segment) does nothing, clear one Trados shortcut.** Trados puts its own **Toggle between Source and Target in Translation Results View** on `Alt+T`, in Studio 2024 and 2026 alike, and the Trados binding wins, so pressing `Alt+T` gave a brief busy cursor and nothing else. Delete that binding once in **File → Options → Keyboard Shortcuts** and `Alt+T` translates the segment; right-click → **Translate active segment** works either way. The keyboard shortcuts page in the help now lists it with the other Trados bindings to clear.
- **A translation request that fails is now recorded.** When the AI provider refused a Batch Translate or Translate active segment request (an overloaded server, an invalid key, an unknown model name), nothing reached the Reports tab, the usage log or the prompt log: the reason appeared only in the Batch Translate log, and was gone with it. The run is now recorded as an error, with the provider's message.
- **Translate active segment now says what it does in the Batch Translate log.** Its lines began "Ctrl+T:", although the command has been on Alt+T since 18/19.20.119 and `Ctrl+T` is Trados's own Apply Translation Result; they now begin "Translate segment:". It also reports what a batch run reports about your termbases: how many AI-enabled terms occur in the segment and go with it, and a warning when terms are loaded but no termbase has its **AI** column ticked, which means no terms are sent at all. Before, a translation that ignored your termbase gave no hint why.
- **An AI assistant can search your Trados translation memories through the MCP server before you have opened the AI Assistant panel.** Until the panel had been shown once since Studio started, `search_studio_tm` answered that no document was open, and `list_resources` left the project's translation memories out of its list. Both now find the open project either way.
- **The SuperMemory bank report said extra files in a bank were never sent to the AI.** It told you to fold any Markdown file other than `brief.md`, `terminology.md` and `style.md` into those three or move it to `reference/`, but such files have been read into prompts since 18/19.20.183. The report now lists them as read. It also now reports what a translation sends: notes marked `audience: assistant` are listed as kept for the AI Assistant chat and the MCP tools, and for a bank large enough to be narrowed per document it gives the most that can be sent and where each document's selection is written.
- **Translate active segment (Alt+T) could refuse to run after you stopped a batch.** Since 18/19.20.190, stopping a Batch Translate run while it was still searching your translation memories left Alt+T answering "A batch translation is already running" until another batch run had finished. The same could happen after a run stopped on an unexpected error. Both now release the run properly.
- **Cache reads on Claude Opus 5.5 and Fable 5.1 are now costed at what Anthropic charges.** The Reports tab, the usage log and the monthly budget counted every cached input token at a tenth of the input price. That is right for most Claude models, but Opus 5.5 charges a twentieth and Fable 5.1 a fortieth, so their cache reads were shown at two and four times their real cost. On a long Batch Translate run, where most of the input is read from the cache, that overstated the whole run.
- **GroupShare translation memories can be used from two places at once.** SuperSearch, the translation memory search in Batch Translate, and the AI tools that read or write a translation memory each keep their own sign-in to a GroupShare server now. They used to share one list of connections, so two of them running at the same time (a SuperSearch during a batch, say) could damage it, or one finishing could clear the connections the other was still using, and a GroupShare memory could then be skipped without a word. File-based memories were never affected.
- **Translate active segment says why it failed, even before the AI Assistant panel has been opened.** When Alt+T was used before the panel had been shown since Studio started, a request that failed (an invalid key, an overloaded server) left the segment empty with no message at all. It now shows the reason.
- **Answering No to the monthly budget warning no longer leaves Batch Translate stuck.** Since 4.20.56, when your monthly AI budget was used up and you answered No to "Start this batch anyway?", the Batch Translate panel stayed as if a run were in progress, with its settings greyed out and nothing for Stop to stop, until every document was closed. It now returns to normal, and the log says the run was not started.
- **The AI Assistant chat no longer reads the whole document again for every message.** To load your SuperMemory bank, the chat worked out the document's subject area on each message you sent: it went through every segment of the open document and analysed the text, while Trados waited. The result was never used, because the bank is sent whole and not filtered by subject. The chat now skips it, which matters most in a long document. What reaches the AI is unchanged. For AI assistants connected over MCP, `get_supermemory_context` no longer guesses a `domain` either; one passed in is still echoed back, and the tool's description now says that neither `domain` nor `query` changes what is returned. Its `client` argument, which once picked a client profile from inside a bank, is ignored for the same reason: a bank is read as a whole. A reply to a request that passes it says so and points to the `bank` argument, which reads a different bank.
- **The usage statistics notice lists everything the startup ping sends, and is no longer cut off.** The notice shown once after an install or update said the ping carried the plugin version, OS, Trados version and system locale. It also sends a random ID made on your computer, whether Windows runs in a virtual machine, the processor architecture, your Windows display scaling and text size, and your Supervertaler UI scale, and the notice now says so. At 125% Windows display scaling or more its last lines, including how to switch statistics off, were cut off; the notice now sizes itself to its text. Nothing about what is sent has changed.
- **The Termbase Editor shows its Bulk Add NT, Merge Selected, Delete Selected and Close buttons again.** They were placed beyond the right edge of the window, at any display scaling, so they could not be seen or clicked: Bulk Add NT and Merge Selected could not be used at all, and deleting worked only from the right-click menu. The editor also grows with Windows display scaling now, and at 125% its term count no longer runs into the NT only box.
- **Dialogs no longer cut off their text at higher Windows display scaling.** At 125% and above, the text in several dialogs grew with Windows' display scaling but the dialogs did not, so text was cut off: the first-run setup (the first window a new user sees), SuperMemory Quick Add, the memory bank file editor, the "Name your existing memory bank" question, and the buttons of the prompt preview and Supported Models windows. These now grow with the display scaling. Three labels were also too small at any scaling and now show their last line: the setup's "existing data folder" note, the memory bank question's explanation, and Quick Add's destination line.
- **Trados could seem to hang at "Start extensions are being executed..." the first time it started with Supervertaler.** On a new installation Supervertaler asks where to keep its data, and it asks while Trados is still showing its startup screen. That window could open behind the startup screen, with no taskbar button, so Trados looked stuck while it was waiting for an answer. It now always opens in front, with a taskbar button, and so do the memory bank migration question and the "update installed" message, the other two windows Supervertaler can show at that point. On an older version, pressing Enter at that screen accepts the suggested folder and lets Trados carry on.
- **Qwen 3.6 Plus (Free) is gone from the OpenRouter list.** OpenRouter no longer offers it, so choosing it could only end in an error. Qwen 3.8 27B (Free) takes its place. As with any free OpenRouter model, the provider may keep what you send, so it is not for confidential work.

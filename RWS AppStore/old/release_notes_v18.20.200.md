## Changelog

### Added
- **Proofread's fixes can now be applied straight from the Reports tab.** Each finding now comes with the corrected translation as well as the advice, shown on its card as **Correction**, and an **Apply** button writes it into the segment. **Apply all**, at the top of the tab, does the same for every finding you have not ticked off, so tick off the ones you disagree with first. A fixed segment is set to Draft. With Track Changes on in the document, the fix is recorded as tracked changes, word by word, so you or a reviewer can see exactly what changed and accept or reject it; with Track Changes off, it is written as a plain edit. Nothing is written over work done since the check: a segment whose source or translation has changed since it was proofread is left alone, and its card says so, as it does for a locked segment and for a correction that would lose or add a formatting tag or a line break. To make that possible, the proofreader now sees each segment's formatting tags, as Batch Translate does, so a correction keeps the bold, links and other tags the translation had; until now it was shown the segments as plain text. Non-breaking spaces and hyphens in the translation are kept too, wherever the correction leaves the text around them alone: an AI writes ordinary spaces, and a fixed "60 °C" would otherwise have been free to break across a line. A source query whose translation needs no change has no correction to apply. Apply all works through the findings a few at a time, so Trados Studio stays responsive, and you can stop it partway: the button reads **Stop** while it runs. The saved report lists each correction too. (Reported by a user.)
- **Proofread now checks translations against your memory bank.** With SuperMemory switched on (Settings → AI Settings → **Include SuperMemory knowledge base in AI context**), a Proofread run sends the active memory bank and `_shared` with its requests, as Batch Translate and Translate active segment (Alt+T) already did. The proofreader treats the bank as the client's instructions: a translation that departs from a term decision, style rule or client preference recorded there is reported as an issue, even where it would otherwise pass as a matter of style, and the issue names the rule it breaks. A point the bank says nothing about is not flagged on its account. So you can check segments that came from 100% matches against a client's current instructions, or run a final check after post-editing, without copying the bank's rules into a proofreading prompt. The bank is sent exactly as for a translation of the same document: notes marked `audience: assistant` stay out, a large bank is narrowed to what the document needs (the same selection, made once per document, and reused if you translated the document first), and the Batch Translate log says what was sent. It goes in the part of each request that is the same for every batch, so a provider that caches prompts charges the cached rate for it after the first request. Clipboard Mode sends no memory bank, for proofreading as for translation. **Preview prompt** in Proofread mode now shows what a run sends – the memory bank included, then the first request's segments – where it used to show the Clipboard Mode text in either mode. (Reported by a user.)
- **Proofread can now check Draft segments on their own.** The scope list has a new **Draft only** option, after **Translated only**. Batch Translate and an AI assistant writing through the MCP server leave their translations as Draft, so this checks the AI's drafts and nothing else. Until now they could only be reached with **All segments**, which also takes every segment already translated or approved, or with a display filter. The segment count under the scope list now matches the Proofread scopes too: with **All segments** chosen it showed Batch Translate's count of unfinished segments.

### Changed
- **The SuperMemory bar now sits above the Supervertaler Assistant's tabs.** The memory bank dropdown, with **Report**, **Open folder** and **Harvest changes**, was inside the Chat tab, where it looked like a chat setting and could not be seen from Batch Operations, Import/Export or Reports – although the active bank is used by Batch Translate, Proofread, Translate active segment and AutoPrompt as well as the chat. It is now at the top of the panel, in view on every tab, so you can see which bank a batch translation or proofread will use before you start it.
- **The termbase list in Settings → Termbases is now in alphabetical order.** It followed the termbases' priority order, so a termbase you had just added appeared at the bottom. Clicking a column header still sorts by that column.
- **Batch Operations now starts on the Default Translation Prompt and the Default Proofreading Prompt.** The prompt list started on "(None – default)", which did not mean either default prompt: it meant no prompt from the library at all, only Supervertaler's built-in instructions. So unless you picked a prompt, a proofread ran without the Default Proofreading Prompt's rules – raise an issue only for an error it can point to, cite the segments behind any consistency claim, propose no other terminology without evidence – and was more likely to report doubtful findings, and a translation, in a batch or with Alt+T, ran without the Default Translation Prompt's guidance on fluency, terminology and register. Each mode now starts on its default prompt whenever you have not chosen a prompt for it, for the project or overall. The first item is now called "(Built-in instructions only)", and choosing it, or turning off the active prompt in the Prompt Manager, is remembered as your choice. If you chose "(None – default)" on purpose before, choose "(Built-in instructions only)" once more to keep it. The prompts that come with Supervertaler are now listed straight under the first item rather than after all of your own, and the list's tooltip says what each kind of item means. Quick Add to SuperMemory still adds terms only to a prompt you chose yourself, never to the Default Translation Prompt.
- **SuperSearch names your languages instead of saying "Source" and "Target".** The results columns, the preview pane and the two search boxes now carry the languages of the document you have open – **Dutch** and **English** in an NL→EN project, say – so you can see at a glance which column holds which language, even when your termbases and translation memories point different ways. A regional variant is named where it matters: *Dutch (Belgium)*, or *English (United Kingdom)* and *English (United States)* in a project between the two. In a narrow panel the box labels shorten to language codes (**NL:**, **EN:**). With no document open, the labels read "Source" and "Target" as before. Switching to a document in a different language pair clears the results on screen, since they were searched the other way round.
- **The update notice now shows everything that has changed since your version.** Its link to the release notes opened the page of the new release alone, so if you were a few releases behind, you never saw what came in between. The link, now **What's new since your version?**, opens the changelog on supervertaler.com with every release newer than the one you have, newest first. The About dialog has a new **Changelog** link to the same page, listing every release.

### Fixed
- **The Reports tab now copes with a proofreading report of any size.** Beyond about 200 findings the cards further down the list were drawn on top of one another, and the list could not be read to the end. Large reports were also slow and heavy: a report of 1,000 findings took close to a minute to appear, with Trados Studio not responding meanwhile, and one of 3,000 could exhaust the window resources Windows allows each program – Studio's own, since the tab runs inside it. The tab now shows the first findings at once at any size, and keeps only the cards in view in existence, so scrolling, ticking off findings and Apply all stay quick however long the list is. Cards look and work as before: text can still be selected and copied, and a right-click still copies a card's issue, suggestion or correction.
- **Saving a term in the Edit term entry dialog no longer erases its abbreviations, URL and project.** The dialog showed those three fields empty, whatever the term held, and saved them back empty – on every Save, even one where you changed nothing. It has done this since v4.19.25 (April 2026), whether the dialog was opened from a TermLens chip, SuperSearch, the TermPicker, the Termbase Editor or Quick Add's **Add & Edit**. It now shows and keeps them. If a term you edited in that time has lost its abbreviation, URL or project, it has to be filled in again by hand; a database backup from before the edit still holds the old value.
- **Saving in the Edit term entry dialog no longer freezes Trados Studio.** After every Save, Supervertaler reloaded every term in your termbases, and every MultiTerm termbase, while Trados Studio waited – and then did it a second time, because it noticed its own change to the database. On a large termbase Studio showed "Not Responding" for up to a minute. Only the entry you saved is now refreshed, which takes a few hundredths of a second, and a Save where nothing changed writes nothing at all. The same goes for editing a cell, adding a row or adding non-translatables in the Termbase Editor, which also reloaded everything every time.
- **Editing a term that is in several termbases now saves every entry you changed.** When TermLens finds the same term in more than one termbase, the Edit term entry dialog lets you switch between the entries. Only the entry on screen when you clicked Save was saved: changes to the others were dropped without a word. Every entry you changed is now saved.
- **Editing a cell of a forbidden term in the Termbase Editor no longer un-forbids it.** Changing any cell of the row – its notes, say – also cleared its Forbidden mark.
- **Ticking all Write boxes in Settings → Termbases now works after sorting the list.** Clicking the **Write** header ticks every termbase at once, skipping the read-only Trados termbases (MultiTerm `.sdltb` and `.ttb`). It recognised those by their place at the bottom of the list, so once the list was sorted by a column, some Supervertaler termbases were left unticked and a Trados termbase could be ticked for writing. After sorting, the same mix-up could also stop a double-click or the right-click **Rename** working on some termbases. The rows are now told apart by what they are, not where they are.
- **SuperSearch now searches a translation memory stored the other way round in your project's direction.** An EN→NL memory attached to an NL→EN project was searched as it was stored: a Dutch term typed in the source box was looked up on the memory's English side, so it found little or nothing, and any hit showed the English on the left. The memory is now searched on the side that holds the language you typed, and its hits are shown the same way round as your document, as termbase hits already were. A hit from a memory or Supervertaler termbase in some other language pair altogether – an NL→DE memory in a multilingual NL→EN project, for example – is marked in amber in the Status column with its own languages, such as **TM (NL→DE)**, because the column headers do not apply to it; the preview pane names its languages too.
- **Track Changes no longer shows a whole segment retyped when only its tags were corrected.** When a segment written through the MCP server's `update_segments` differed from the old one only in a tag – Studio's generic bold tag replaced by the file's own, say, which look the same even in full tag view – the whole segment was recorded as struck out and inserted again, with nothing visible to say what had changed. The tags are now replaced as they are, and only text changes show as revisions: a tag correction on its own shows nothing, and a tag correction plus a changed word shows that word. The same goes for a tag pair added or removed around unchanged text, such as bold taken off a "1." that is not bold in the source. Where a tag moves to other words, or tags are added or removed while the text changes too, the segment is still recorded as a whole-segment change, and the tool says so. Each result now says how the segment was recorded (`revisionMode`: `word`, `tag-only` or `whole-segment`) and how many tags were replaced (`tagsReplaced`), so the assistant can tell you exactly what it did. A segment in which a tag itself carries a tracked change is now always recorded as a whole-segment change: the word-level path could not see such a change, and would have written the tag back as though nobody had touched it.
- **`check_tags` no longer counts tags in text struck out with Track Changes.** After a segment was rewritten with Track Changes on, the check read the deleted old text as part of the target, so a segment whose tags had just been repaired was still reported as carrying the tag that had been removed, until the changes were accepted. Tracked deletions are now left out, as they already were from the tag count.

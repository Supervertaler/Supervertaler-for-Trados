## Changelog

### Added
- **Supervertaler for Trados now also runs in Trados Studio 2022.** A third build, numbered 17.20.199, joins the Studio 2024 and 2026 builds with the same features, including MultiTerm `.sdltb` termbases, which Studio 2022 reads the same way as 2024. Install it from the RWS App Store inside Studio 2022, as with the other builds. One licence covers every Studio version you use on the same computer and Windows account, and all of them share one data folder, so your settings, termbases, memory banks and prompts are the same in each. RWS ends its own support for Studio 2022 on 31 December 2026.
- **A team folder for sharing memory banks and prompts.** In Settings → General → Team folder, point everyone in a team at the same folder on your file server: Supervertaler then takes the memory banks (including `_shared`) and the prompt library from there, so the whole team works from the same knowledge and prompts. Everything personal stays in each person's own data folder: the licence, settings, API keys and termbases. Choosing a folder that is still empty offers to copy your current memory banks and prompts into it; your own copies stay where they are. If the team folder cannot be reached when Trados Studio starts, Supervertaler uses your own data folder for that session and says so in the AI Assistant, rather than switching silently. The setting takes effect at the next start of Trados Studio.
- **Move your data folder from Settings.** Settings → General now shows where your data folder is, with **Open** and **Move…** buttons. Move copies the whole data folder to a new, empty folder when you click OK, and Supervertaler uses the new one from the next start of Trados Studio. Your old folder is left exactly as it is until you delete it. Settings that point into the data folder, such as the termbase, are updated in the copy, and the termbase database is copied safely even while Trados Studio has it open. If anything goes wrong, or you cancel, the partial copy is removed and nothing changes. Choosing a folder that already holds a Supervertaler data folder – your old one, or one restored from a backup – switches to it as it is, without copying. Until now the data folder could only be moved by hand, by editing a configuration file where one mistyped backslash could send Supervertaler Workbench and the MCP server to a different folder from Trados Studio.
- **The OpenAI list in AI Settings now offers OpenAI's three current models: GPT-6 Astra, GPT-6.1 Sol and GPT-6 Luna.** They are the three OpenAI itself puts forward, one per tier: **Astra**, its most capable model, at $10 / $50 per million tokens; **GPT-6.1 Sol**, released on 29 September 2026, close to Astra's quality at a fifth of its price, $2 / $10; and **Luna**, for high-volume work, at $0.10 / $0.50. All three have a 1M-token context. GPT-6.1 Sol is the new default OpenAI model for a new installation. They replace GPT-5.6 Sol, Terra and Luna and GPT-5.4 Mini, in the OpenRouter list too. If you have one of those selected, nothing changes for you: it appears in the custom model ID field, keeps working and is still costed. The cost of the new models is counted at OpenAI's published rates, including their much cheaper cached input. SuperBench's default OpenAI model is now GPT-6.1 Sol. In the AI Assistant chat, Astra and Luna can look things up in Trados Studio (your projects, statistics, translation memories and termbases) as before. GPT-6.1 Sol cannot: OpenAI does not let it use those lookups through the connection Supervertaler uses, so the chat sends it the question without them rather than failing on every message. The current segment, its terms and its TM matches still go with every message.
- **An AI assistant connected through the MCP server can now keep your memory banks up to date.** Four new tools let it record a decision you reach together during a job, instead of leaving it behind in the chat: `append_terminology_row` adds a term to a bank's terminology table, with its scope and the reason for it; `update_supermemory_section` rewrites one section of a file, such as a rule in your style guide, and leaves the rest of the file exactly as it was; `write_supermemory_file` creates or replaces a whole file; and `read_supermemory_file` reads one. The assistant writes only when you ask or agree, and always names the bank: a write never goes to the active bank by default, and a bank that does not exist is an error, not a new bank. A file that has changed since the assistant read it – in Obsidian, in the Library tab, by a colleague in the team folder or by Supervertaler for memoQ – is not overwritten; the assistant is given the file as it now stands. A term that already has a row is refused, and the assistant is shown that row. The `reference/` folder is never written, and the `_shared` bank only when you have agreed. Each file keeps its own line endings, so a change of one row shows as one row in Obsidian's or Git's history. The previous version of every changed file is kept in your data folder under `backups\memory-banks`, one copy per file, and never in the bank folder itself. While a team folder set in Settings could not be reached when Trados Studio started, the assistant cannot change memory banks at all.

### Changed
- **A licence now counts only for the computer and Windows account it was activated on.** A data folder used from more than one computer or Windows account – shared with colleagues, or synced between your own computers – now keeps a separate licence record for each, with its own trial and its own activation, so nobody's activation can overwrite anyone else's. If you have renamed your computer or reinstalled Windows since you activated, Supervertaler tells you so when Trados Studio starts and in Settings → Licence: re-enter your licence key there to activate it again. If the key has no activations left, the earlier activation recorded in your data folder is released to make room once it has gone a day unused. On a computer whose name and Windows account have not changed, nothing changes.
- **SuperSearch's Beijerterm web resource is now Beijer Dictionary.** The dictionary has a new name and a new address, BeijerDictionary.com, and the built-in web resource uses both. If you had it switched on, it stays on.

### Fixed
- **Install Update now installs into the right Trados Studio.** The update notice's **Install Update** button only ever looked in Studio 2024's plugin folders. In Studio 2026 it reported success without changing anything, and on a computer with both Studios it could replace the Studio 2024 copy with the Studio 2026 build, which Studio 2024 cannot load, so Supervertaler disappeared from Studio 2024. It now installs over the exact copy that is running: the same Studio, the same install location and the same file. If Supervertaler went missing from Studio 2024 after an update in Studio 2026, reinstall it from the RWS App Store in Studio 2024. Three related changes help shared computers where Supervertaler is installed "for all users". Someone who is not allowed to change the shared installation is told that their administrator installs updates, instead of seeing a failed download. Supervertaler no longer refuses to load at every start when it finds a newer version it cannot switch to; it carries on with the version it has. And a download that fails part-way no longer leaves a damaged plugin file behind.
- **Costs for GPT-5.6 Sol, Terra and Luna now match what OpenAI charges.** Supervertaler was still costing them at their launch prices, above what OpenAI charges now: Sol at $5 / $30 per million tokens where it is $4 / $20 (an OpenAI promotional price, available at least until 21 November 2026), Terra at $2.50 / $15 where it is $2 / $12, and Luna at $1 / $6 where it is $0.20 / $1.20. Cached input on all three was counted at half the input price; OpenAI charges a tenth. The Reports tab, the usage log and the budget warning use the corrected prices for every call from now on. Calls already in your usage log keep the cost they were recorded with.
- **Soft returns no longer come back as hard returns.** When a segment's source had a soft return (↵) and its translation came back on two lines, the target could get a Windows line break instead: a carriage return, which Trados shows as a pilcrow (¶) and saves as a hard return. The client receiving the file then finds hard returns that are not in the source. Batch Translate and Translate segment were the main route: the code that reads the AI's reply joined a segment's lines with Windows line breaks, and a segment without formatting tags was written exactly as it came. Clipboard Mode replies in the numbered format, `update_segments` and the AI Assistant's Apply to target could do the same with text that already had Windows line breaks. Every line break Supervertaler writes into a target now matches the source: a soft return where the source has a soft return, a hard return where the source has one inside the segment, the source's own line-break tag in file types that use tags, and a space where the source has no line break to match, so the AI can no longer add line breaks the source does not have. A segment with two line-break tags also no longer gets the first one twice, which the Tag Verifier reported as a duplicated tag.
- **A project's settings are no longer lost when the file is in use at the moment they are saved.** When you click OK in Settings, or a project's memory bank or prompt changes, Supervertaler saves that project's choices to a small settings file. If anything else had that file open at that very moment – a second Trados Studio, a virus scanner, a backup or sync tool – the save failed without a word, and the project could come back next time with its previous prompt or memory bank. Supervertaler now saves in a way that works while other programs are reading the file, and waits a moment for one that has it locked; if it still cannot save, the previous settings stay exactly as they were.
- **The status banner in Settings → Licence no longer runs past the right edge of the window.** Its right-hand border was never visible; the banner now ends inside the page at any window size and display scaling.
- **AutoPrompt no longer refuses a complete prompt because it contains a long numbered list.** Before saving, AutoPrompt checks that a generated prompt was not cut off, and one of its checks looks for the OUTPUT FORMAT section. It found the sections by their numbers, so a numbered list inside the prompt – the previous translations, say – that ran past the section numbers took the place of the real sections after it. AutoPrompt then reported that the prompt "stops at section 31" with no OUTPUT FORMAT section, and refused to save it, although the section was there. Running AutoPrompt again, as the message advised, would usually bring back the same list and the same refusal. It now recognises the sections by their headings. A prompt that really is cut off is still refused. (Reported by a user.)
- **Quick Add to SuperMemory no longer rewrites your whole terminology file, and puts the row in the right table.** Adding a term rewrote every line break in `terminology.md` as a Windows line break, so in a file with Unix line breaks – and many are – one new row showed in Obsidian and in Git as a change to every line. It also put the row after the last table row anywhere in the file, which in a file with several tables, such as a table of rejected variants at the end, is the wrong table. It now changes only the row it adds, puts it in the first table with a Scope column, and refuses a term that already has a row, showing you the one there is. If the file has no table with a Scope column, it says so rather than starting a new table. The previous version is kept in the backups folder.
- **The Library tab's editor saves memory-bank files safely.** It wrote the file in place, so a crash during the save, or a program reading the file at that moment, could meet a half-written file. It now saves in one step, keeps the previous version in the backups folder, and notices a change made by someone else from the file's content rather than its time stamp.
- **An AI assistant now sees every project template you can choose in Trados Studio.** The MCP server's `list_project_templates`, and the same lookup in the AI Assistant chat, only looked in each Studio version's Project Templates folder. Studio's **New Project** → **Use Settings from** list also holds every template you have added from somewhere else – a backup folder, a synced drive – and those were missing, often the very templates you keep for recurring clients. It now lists every template Studio has registered, in every installed Studio version and wherever the file is stored, plus any in the Project Templates folders. Each says which Studio version it belongs to and whether Studio lists it, and a template Studio still lists but whose file has been moved or deleted is shown as missing.

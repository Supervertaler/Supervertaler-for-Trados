## Changelog

### Added
- **Batch Translate now gives the same sentence the same translation every time it occurs.** The AI translates each segment on its own, so a sentence that came up twice in a run often came back worded two ways – in recent runs, about half of the repeated sentences did. Now every later occurrence gets the translation of the first one, across all the files in the run, and the same goes for a translation note (`[[TC: …]]`) on it. A segment the run does not overwrite – a TM match, a locked segment – keeps its translation, and its empty repetitions get that one. If such segments already disagree with each other, nothing is changed and the log lists them. A repetition the AI left empty is filled from its first occurrence too. Nothing sent to the AI changes: every segment is still translated, in the same batches. The log ends with a line such as *586 segments – 130 repetitions aligned to their first occurrence*, and the backup TMX keeps the AI's own version of each aligned repetition in a note. A repetition is the same text exactly – same capitals, spaces (a non-breaking space is not an ordinary one) and tags. On by default: **Settings → AI Settings → Keep repetitions consistent in Batch Translate**.
- **Proofread can now check the translation on its own, for a quick final read after post-editing.** Tick **Translation only (no source)** on the Batch Operations tab, in Proofread mode, and the proofreader is sent the translation without the source text. It checks spelling and typos, words doubled or left behind while editing, grammar, punctuation, number formats and spelling that varies across the document, and, with SuperMemory on, the memory bank's language and style rules and any term decision that can be judged from the translation alone, such as a word the client never wants used. Without the source it cannot check accuracy, omissions or terminology, so it is told not to try, and not to guess at what the source says. No termbase is sent either: whether a term is right depends on the source term it translates. Leaving the source out takes roughly half off the segments and the document context sent with them; the instructions and the memory bank are sent either way, so on a fully translated document a run costs roughly a third to a half less, the most when the memory bank is small. Segments not yet translated are left out of the document context altogether: on the example project, where only a fifth is translated, a run took 10,000 input tokens instead of 20,800. Findings come with corrections, and **Apply** writes them after the same checks as before, against the segment's source and tags. The Reports tab and the saved report say when a check was made on the translation only. The box starts unticked every time Trados Studio starts, so a full check is never skipped by accident, and it takes the place of **Send TM matches to the AI** and **Retry segments left empty**, which only apply to Batch Translate and are now hidden in Proofread mode. It works in Clipboard Mode too, and **Preview prompt** shows what is sent. (Requested by a user.)
- **GPT-6.1 Sol can now look things up in the AI Assistant chat.** Since 199 it answered without the Studio Tools – your projects, statistics, translation memories and termbases – because OpenAI lets this model use tools only through its newer Responses API, not the connection Supervertaler used. With your own OpenAI key, the chat now talks to GPT-6.1 Sol through the Responses API, so it can call those tools like the other models. Supervertaler asks OpenAI not to store these conversations: each request carries the whole chat instead. The chat and the prompt log show the tokens OpenAI reports rather than an estimate, its reasoning included, and their cost counts OpenAI's cache writes at its published rate. Every other model, and GPT-6.1 Sol through OpenRouter, works as before. (Requested by a user.)
- **SuperSearch can now look terms up on JoostdeVree.nl.** The Dutch encyclopedia of building and architecture gives the English for many of its entries, so it works in both directions: search a Dutch term to read its entry, or an English one to find the Dutch entries that give it. It is in the Dutch group of the **Web** picker, switched off like the other Dutch sites; tick it to add it to your searches.
- **The shared memory bank is there from the start.** The shared bank, `_shared`, holds your house defaults – the terms and style rules that apply whatever the client – and goes with every request, under whichever memory bank is active. Nothing used to create it, so you had to know it was a folder to make in File Explorer. Supervertaler now makes it when Trados Studio starts, if it is missing, with a starting brief, terminology table and style guide, so it is in the memory bank list in the SuperMemory toolbar and in **Settings → Library**. With a team folder, it is made there, for everyone. It sends nothing to the AI until you write something in it, and a shared bank you already have is left exactly as it is, including any file you deleted from it. Supervertaler for memoQ makes it the same way.
- **The terms of use are linked where they apply.** Supervertaler now has [terms of use](https://supervertaler.com/terms/), covering the trial, your licence, subscriptions and refunds, and what you are responsible for when you use AI. The notice about anonymous usage statistics, which every new user sees once, says that using the plugin means agreeing to them; **Settings → Licence** says the same beside **Activate**; and the About dialogue lists them under the privacy policy. Each links to the page. Nothing asks you to tick a box, and nothing changes in how the plugin works.
- **Add segments to SuperMemory (Ctrl+Alt+Shift+A): the part of a document you have reviewed becomes the reference for the rest.** Select rows in the editor by their numbers – click the first row's number, Shift+click the last – and press **Ctrl+Alt+Shift+A** to copy those segments, source and translation, into a memory bank. Batch Translate and Translate active segment (Alt+T) then follow their approved wording for the rest of the job: translate and review the definitions of a contract, say, or the claims of a patent, and the body or the description is translated with them in every prompt. Until now that took an AI assistant connected through the MCP server. The window opens with the range you selected, and you can change it by segment number; in a document made of several files, choose the file as well. The command is also on the editor's right-click menu, but from there the range starts at the active segment: right-clicking in a segment's text makes Trados Studio drop the rows you had selected. Only confirmed segments are taken, unless you untick **Only confirmed segments**, and a segment without a translation is always left out. The segments go into the bank's `brief.md`, under **## Reference translations**: the one bank file a translation always sends whole, where a large bank's terminology and other files are narrowed down to what each document needs and would lose whole segments. Adding segments again replaces that section, so one job's reference translations do not stay in the bank for the client's next job. Before anything is written, the window shows exactly what will go in and how many tokens it adds to every translation request. It warns above 4,000 tokens, and refuses a range that would take the bank's own files past the 24,000 tokens a translation sends, since parts of the bank would then be cut from every prompt. It also tells you when the bank you chose is not the active one, which translations do not read. The rest of `brief.md` is kept exactly as it was, its previous version is saved in your data folder, and nothing is written if the file was changed in Obsidian or by a colleague since the window opened: the window then shows the file as it is now, for you to try again. Writing to `_shared`, which goes with every client's jobs, asks first.

### Changed
- **The tabs of the Supervertaler Assistant panel are easier to tell apart.** Windows outlines them in a grey so light that **Chat**, **Batch Operations**, **Import/Export** and **Reports** ran together. Each tab now has a clearly visible outline; everything else about them is as before.

### Fixed
- **Re-importing a combined export of a merged document no longer writes an edit into the wrong file.** When several files are open together as one document, Trados Studio numbers each file's segments from 1, so a bilingual export made with **Combine into one file** has a segment 3 for every file. Re-import matched rows by number alone and took the last file's segment for each number: a row from an earlier file was compared with the wrong segment and usually skipped as no longer matching the exported file, and where the two segments read the same – a figure label such as "Fig.", say – the proofreader's edit was written into the other file's segment without a word. Each row is now matched by its file as well as its number, from the **File** column in a DOCX or the 📄 File: line in a Bilingual Text file, so edits in every file go where they belong, and the re-import messages name the file. A row that cannot be placed in one file is skipped and named, never guessed. Exports of a single file, and separate exports per file, were not affected.
- **The About dialogue no longer says the plugin collects no data.** Hovering over **Source code available for security audit** said the plugin contacted only your AI provider and the licence server, with "no telemetry, no tracking, no data collection" – while it also checks the RWS AppStore for updates and sends one anonymous usage ping per session unless you switch it off. It now lists what the plugin connects to by itself – the licence services, the RWS AppStore and that ping, besides your AI provider – and points to the privacy policy for the details.
- **Proofread no longer gives one file's finding to the same-numbered segment of another.** When several files are open together as one document, Trados Studio numbers each file's segments from 1, and Proofread could send segment 3 of two files in the same request. The AI's verdict for "segment 3" was then given to both: a second card on the Reports tab, with **Also add issues as Trados comments** ticked a comment on a segment the issue was not about, and an **Apply** that would have written that correction into the other file's segment. Each request now holds the segments of one file only, and says which, so every verdict lands on the segment it is about. In such a document the cards, the Batch Operations log and the saved report name the file as well as the number – "Segment 3 of Acme - Text.docx" – and the cards are listed file by file. A document of one file is checked exactly as before.
- **A Batch Translate run now writes only into the document it was started in.** It used to write each translation into whichever document was active at that moment, so switching to another document while a run was going aimed the rest of its translations at the wrong one.
- **Segments Supervertaler rewrites now say you edited them, as a segment you change by hand in Trados Studio does.** A segment written by an AI assistant through the MCP server (`update_segments`, `find_and_replace`) or by Proofread's **Apply** kept the label it had before: a TM match still said it was an unedited TM match, machine translation still said it was unedited machine translation, and a segment with no label kept none. Trados Studio did label the change, but Supervertaler put the old label back when it set the segment's status afterwards – so anyone filtering a return package on unedited matches, or judging how much post-editing went into it, saw segments nobody had touched. Every segment whose text Supervertaler changes now reads as an interactive edit, like one typed in the editor, with its earlier label kept as the previous origin and your name and the time recorded. A segment already marked as your edit keeps its history, a write that leaves the text as it was changes nothing, and adding or changing a comment leaves the label alone.
- **A segment with unaccepted tracked changes is no longer reported as written when it was not.** With Track Changes off, Trados Studio protects tracked changes nobody has accepted or rejected yet, and quietly declines any edit that would replace them – from a plugin as from the keyboard. So an AI assistant writing through the MCP server's `update_segments` was told such a segment had been written while it stayed exactly as it was, and **Apply** on the Reports tab, Batch Translate, Clipboard Mode's **Paste from Clipboard**, Translate active segment, AutoTagger, QuickLauncher's text transforms, the bilingual re-import, SuperSearch's **Replace** and the MCP server's `find_and_replace` and comment tools could all do the same. Supervertaler now reads every segment back after writing it. A segment Studio did not change is reported as not written, with the reason – accept or reject its tracked changes, or switch Track Changes on, and try again – wherever that feature reports a failure: the Batch Operations log and its count of failed segments, a message for a single segment, the Reports card, the SuperSearch status line, or the AI's tool result. Nothing is written over tracked changes that nobody has reviewed. With Track Changes on, such a write goes in as a tracked change, as before.
- **The Batch Operations log now names a segment by the number Trados Studio shows.** When a segment could not be written, the log named it by Supervertaler's own count of the segments, which starts at 0. In a document made of several files, where Studio numbers each file's segments from 1, the second segment of the second file was "segment 14" from Batch Translate and "segment 0" from Translate active segment (Alt+T). Batch Translate, Translate active segment, Clipboard Mode's **Paste from Clipboard** and the bilingual re-import now name it as Studio does, with the file in a document of several files – *Failed to write segment 2 of Acme description.docx* – and so do the log's other lines about a single segment, such as one left empty because the AI's reply held more than a translation. A segment you split in Studio is named as Studio names it, such as *segment 331 a*. When Clipboard Mode refuses a reply, it also gives the number the segment has in the AI's reply, the one to ask the AI about. And the messages from AutoTagger, and from Translate active segment when the Supervertaler panel is not open, now say which segment they mean: the cursor may have moved on while the AI was answering.
- **A segment's comments no longer multiply when a fix is written as a tracked change.** Writing over a segment with a comment while Track Changes was on – Proofread's **Apply**, or an AI assistant through the MCP server – added a copy of the comment each time: a segment with one comment showed it three times after two fixes. Trados Studio keeps the comment in both the deleted and the inserted text of a tracked change, and Supervertaler carried both copies into the new text. A comment in deleted text now stays with the deletion until someone accepts or rejects it, and a comment is carried across once however many copies it has, so a segment that already shows a duplicate loses it at its next fix.
- **Find and replace no longer finds or changes words a tracked change has deleted.** A deleted word stays in the file, struck through, until someone accepts or rejects the change, and the MCP server's `find_and_replace` and SuperSearch read it as if it were still part of the segment. So a search could find words the segment no longer says, the preview an AI assistant showed you ran the old and the new wording together – "uitschakeltinschakelt" for a segment that reads "inschakelt" – and a replace could change a word inside the deletion. Both now read a segment as it would be with its tracked changes accepted: deleted text is not searched, shown or changed, and the before and after you are shown are the corrected wording. A match that runs from one side of a tracked change to the other is skipped and reported, as a match across a tag already was, for you to edit by hand. SuperSearch's **Replace** now also works in segments with tags: in the file open in the editor it refused every segment that had any tag, wherever the match was, saying the match spanned inline tags. And **Replace All** in a file not open in the editor no longer leaves part of a replace behind in a segment it reports as skipped.
- **With Track Changes on, a find and replace now marks only the words it replaced.** The MCP server's `find_and_replace` and SuperSearch's **Replace** and **Replace All** (in the file open in the editor) recorded even a one-word replace as a change to the whole segment: the old sentence struck through and the new one inserted after it, so a reviewer had to read both to find the one word that changed. They now record it word by word, the way `update_segments` and **Apply** on the Reports tab already record a rewrite: the old word struck through, the new one inserted beside it, and the rest of the segment, its tags and its comments left as they were. A segment that already holds tracked changes is still recorded as one whole-segment change, as `update_segments` records it, and you are told so: in the AI's tool result (each change's `revisionMode` and `warning`) or on the SuperSearch status line. With Track Changes off, nothing changes.
- **Proofread no longer loses every finding when the AI puts its verdict on its own line.** Each verdict is meant to read `[SEGMENT 0026] ISSUE`, on one line. Claude Sonnet 5.5 wrote the segment number on one line and ISSUE or OK on the next, and Supervertaler read none of it: every segment counted as OK, and a run that had found three real errors reported "No issues found". Both layouts are now read. And should a reply ever leave a segment's verdict unreadable, the Batch Operations log now says how many, instead of passing them as OK without a word.
- **"Also add issues as Trados comments" now does what it says.** The box in Batch Operations, in Proofread mode, had never done anything: ticking it added no comments. Now, when a proofreading run ends, each issue is added to its segment as a Trados comment – the issue and its suggestion – so you, or a reviser you send the file to, can read them in the editor. Each comment starts with "AI proofreader" and the model that found the issue, for example "AI proofreader (Claude Opus 5.5):", so it cannot be taken for a colleague's; to leave that out, untick **Start Proofread comments with "AI proofreader (model):"** in **Settings → AI Settings**. **Apply** and **Apply all** on the Reports tab follow the same box: with it ticked, each fix they write gets its issue as a comment too, so whoever accepts or rejects the tracked change can see why it was made. Each segment gets one comment from the proofreader: a segment that already has one is left alone, so running the check again – which words the same issue differently every time – or applying a fix the run already commented on does not add a second. A different issue found there later is on the Reports tab. With the label switched off, Supervertaler cannot tell its own comments from a colleague's, so then only an identical comment is left out. The comments go in a few at a time, so Trados Studio stays responsive with hundreds of issues – Trados Studio takes about a fifth of a second over each, so a few hundred take a minute or so; the Reports tab shows how far it has got, and unticking the box stops it. The Batch Operations log then says how many were added and names any segment that could not take one. Comments are part of the document's unsaved changes: save the document to keep them.
- **A proofreading report remembers what you applied and ticked off, even when another program has its file open.** The Reports tab saves its state after every **Apply** and every ticked-off card, so that a report put back after a restart shows only what is still open. When a virus scanner, the Windows indexer or a sync tool had that file open at the same moment, the save was refused with "Unable to remove the file to be replaced", and the cards you had dealt with came back next time. The save now waits a moment for the file to be free, and if it still cannot write, it leaves the previous file whole. The file that tells Supervertaler where your data folder and team folder are is written the same way.
- **A copy of Supervertaler installed before RWS approved it is now offered the signed App Store copy.** A build sent to you ahead of its App Store release is not signed by RWS, so Trados Studio warns about an unsigned plug-in every time it starts, and until now nothing told you when the signed copy of that same version came out: you stayed on the early copy until the next release. Once the App Store has the version you are running, the update notice now offers its signed copy, and **Install Update** puts it in place of the early copy, so the warning goes. A copy installed from the App Store is not affected. Early copies are also now named as the App Store names its own, so installing from the App Store later replaces an early copy instead of loading the plugin twice, which stopped Trados Studio from starting.
- **SuperVoice can now select words in a segment that contains tags.** In a segment with a formatting tag – a figure reference in bold, say – selecting any word after the tag, by saying it or by its number, was refused with "is inside another word – say more words". Segments without tags were not affected. The numbered word list (**numbers**, **source numbers**) also showed the tags' code and numbered parts of it, such as "cf", "bold" and "True", as words, so every number after a tag pointed at the wrong word. The list now numbers only the words and shows each tag as a small purple marker, without a number, where it sits in the segment.
- **The diagnostic log no longer fills up with the same termbase line every two seconds.** With **Enable diagnostic logging** switched on and a MultiTerm termbase in the project, Supervertaler wrote down which termbases it had found every two seconds, whether anything had changed or not. That was over a third of the log, and it pushed out the earlier history a bug report needs. It is now written only when it changes.
- **Local models in Ollama no longer think before every answer.** Newer models such as Gemma 4 and the Qwen 3 family work through a hidden reasoning step by default, and Supervertaler did not switch it off, although it never uses the reasoning. Every Batch Translate request and every AI Assistant reply waited for it: on a computer without a graphics card, one paragraph took over three minutes instead of eight seconds. The reasoning also used up the request's output allowance, so a batch could come back incomplete. Supervertaler now asks for the answer directly. Models without a reasoning step, such as TranslateGemma, are not affected.
- **Local models in Ollama now get room for the whole prompt.** Unless told otherwise, Ollama gives a model a small working memory – 4,096 tokens on a computer without a graphics card – and quietly cut a longer prompt down to fit. Supervertaler's instructions, glossary and memory bank come first in the prompt, so they were what went, and the model still translated the segments, without them and without a warning. Supervertaler now asks Ollama for room for the whole prompt and the answer.
- **A local model's answer made from part of the prompt is no longer used.** When a model holds fewer tokens than the prompt – Aya Expanse 8B holds 8,192, and a prompt with a memory bank can be twice that – the request now fails with a message saying so, instead of returning a translation made without your instructions. Batch Translate and Proofread stop at the first such batch, rather than reading every batch for minutes only to fail the same way. This applies to Ollama and to OpenAI-compatible servers such as LM Studio.
- **Local models stay loaded during a break.** Ollama unloaded a model five minutes after the last request, and the next one then had to read the whole prompt again, which takes a quarter of an hour or more on a computer without a graphics card. Supervertaler now asks Ollama to keep the model loaded for four hours.
- **A model on your own computer now gets 30 minutes to answer.** The time limit for Ollama went by the model's name and gave the largest models the shortest time, three minutes, although without a graphics card the first request of a job can need a quarter of an hour. It is now 30 minutes for every model, unless you set your own under Settings → AI Settings → **Timeout**, which is now also shown, and applies, for OpenAI-compatible servers such as LM Studio. Those were held to two minutes.
- **A request that runs out of time no longer ends Batch Translate without a word.** It was taken for a click on Stop, so the run simply ended. It is now reported as a failed batch, with the reason, and the run carries on with the next one.
- **With a model on your own computer, the memory bank is now narrowed down to what the document needs, as it is with cloud models.** For a large memory bank, Supervertaler first asks the model which articles and house rules the document needs, and gave it 90 seconds to answer. Without a graphics card a local model needs several minutes for that, so it always gave up and sent every article and rule – including ones written for other language directions and kinds of text. With Ollama or an OpenAI-compatible server such as LM Studio it now has as long as the **Timeout** setting allows (30 minutes unless you set your own). It is asked once per document, and the Batch log says it can take a few minutes; with a graphics card it takes seconds.
- **Supervertaler checks the App Store for updates at most once a day, as intended.** It kept the answer for 24 hours in a folder it also cleared at every start, so in practice it asked the App Store again every time Trados Studio started.
- **AutoPrompt now refers to segments by the numbers Trados Studio shows, in a document made of several files.** When a project's files are open together as one document, Studio numbers the segments of each file from 1, but the document Supervertaler sent to the AI was numbered from 1 to the end. So every segment AutoPrompt pointed to in the prompt it wrote – a defect to correct, passages to keep in line – sent you to the wrong row: with a figures file of 7 segments ahead of a text file of 444, segment 32 of the text file was called segment 39. The document is now numbered as Studio numbers it, with each file's name where it starts, and AutoPrompt is asked to name the file and number of any segment it mentions and to quote a few words of it beside the number. The document sent with Batch Translate and the AI Assistant chat is numbered the same way, and the MCP server's `get_prompt_context` now numbers it too and lists the files, so an AI assistant writing a prompt for you gets the numbers right as well. A one-file document is sent as before, except that a segment you have split or merged in Studio now carries the number Studio shows for it. Prompts written before this version are not changed: in a merged document, check their segment numbers against the text they quote.
- **Gemini 3.8 Flash and Gemini 3.1 Pro no longer bill for hidden thinking on every request.** Gemini models think before they answer, and Google charges that thinking at the same rate as the answer, although you never see it. Supervertaler had switched the thinking down for the 3.5 models only, so 3.8 Flash and 3.1 Pro thought as much as Google's defaults allow. In a test with one short sentence, 3.8 Flash charged for 718 thinking tokens on top of a 21-token translation – about $2.80 per 1,000 sentences, where the translations themselves come to about 8 cents. Each model now thinks as little as it is allowed to. 3.8 Flash charged nothing for thinking in the same test, so the cost fell to those 8 cents; 3.1 Pro cannot go below its Low setting and still thinks, but it about halves, from 1,070 thinking tokens (roughly $13 per 1,000 sentences) to 524 (roughly $7). Real segments vary, and a longer or harder passage thinks for longer. The temperature is unchanged. This covers Batch Translate, Proofread, AutoPrompt and the AI Assistant's chat; the Assistant's chat with Studio Tools still uses Google's default.
- **New memory bank no longer turns `_shared` into `shared`.** Typing `_shared` as the name of a new memory bank lost its leading underscore, which made an ordinary bank called "shared" that was never sent as the shared one, with nothing to say so. It now makes the shared bank, and leaves the active bank as it was: the shared bank is sent under whichever bank is active, so there is no need to switch to it. Now that the shared bank is made when Trados Studio starts, you will usually be told it is already there.

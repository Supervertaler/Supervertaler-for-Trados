## Changelog

### Added
- **SuperVoice has a pane of its own.** Until now the microphone button and everything the voice system said lived in the TermLens header – invisible to anyone who does not keep TermLens open, and gone within seconds either way. That was fine when the strip only echoed "confirm"; it stopped being fine when selection arrived and the messages started carrying what you actually need to read: which of four readings was taken, why a word could not be heard, what the recogniser really returned. **View → SuperVoice** opens a dockable pane with the microphone, its state, and the recent utterances – newest at the top, what was heard beside what happened to it, kept rather than flashed. Green is a command that ran, amber a selection declined with a reason, red a command that tried and failed; ordinary speech that matched no command is grey, because it is not an error. It opens on the right, beside Translation Results, as a tab – the microphone's state is already visible all the time in the TermLens header, and what this pane holds is the history, which is read occasionally rather than watched. Dock it anywhere and Studio remembers; sized to a few rows it always shows the last thing that happened. The TermLens button works exactly as before. The small black floating strip no longer appears while the pane is open: it was only ever a fallback for when nothing else could show the state, and with the pane there it was clutter over the editor. Issue #129.
- **"press enter"** (or "hit enter") presses Enter – the default button of whatever dialog is open. Two words on purpose: a bare "enter" is ordinary speech.
- **"select all"** selects all the text in the active segment (Ctrl+A); **"select everything"** works too. Added on request, and it found a real bug on the way in: the second listening pass that makes "select the duty cycle" reliable was re-hearing "select all" against the segment's own words, finding no *all*, and reducing it to bare "select" – so the command was heard perfectly and did nothing. A phrase that *is* a command, word for word, is now left alone by that pass. Issue #129.
- **Select by number: the words the voice model cannot hear can now be selected by saying a number.** Say **"numbers"** and a small popup numbers every word of the target segment – hyphenated compounds as one unit, and the words the model cannot hear marked in yellow; **"source numbers"** does the same for the source. Then **"select 12"** selects word 12, **"select 12 to 14"** selects the span, and **"cancel"** closes it. The popup also opens **by itself** when a selection fails because the word is not in the model's vocabulary, with the reason as its title – that failure is exactly what the numbers exist for. It cannot mishear a word it was never asked to hear, and it works in any language. The popup never takes focus, because selection is made by driving Studio's own search and that needs the editor to keep it; the number words are in the recogniser's vocabulary only while the popup is open, since sixty extra words competing for every sound is how "term eight" once made the article "a" unsayable. "to" heard as "two" is tolerated ("seven two nine" reads as 7–9), and two single digits with nothing between them are the digits of one number ("four two" is 42 – said deliberately when "forty two" is misheard). Numbering runs past 99 but only 1–99 can be said. **Two layouts**, switched from a link in the popup's own corner and remembered: **sentence** – the segment reproduced as it reads, punctuation and all, with a small muted number after each word like a footnote, so you read the sentence first and the number second – and **chips**, number then word on a grid. Because the popup can never take focus, it has three ways out that do not need it: the Escape key (through the same route the TermLens popup uses), "cancel" or "escape" spoken, and a × in its corner; it also closes on any successful selection, whether by number or by saying a word, and on a segment change. It does not open by itself while you are dictating or while Studio is not the active window. Issue #128.
- **The memory bank follows the open project on start-up too, and a new project gets the bank named after it.** The bank already switched with the document – a project with no recorded bank cleared to none rather than inheriting the last one – but only through the document-change event, which never fires for a document already open when Studio starts: the previous session's bank stayed loaded whatever the project. It is applied at start-up now. A project with no recorded bank also takes the bank whose name is the project's own (exact match only, and recorded as the project's bank from then on), which is how the banks are named. No switch happens while a batch run is in progress; it follows when the run ends. A bank picked from the dropdown is recorded as the project's and sticks, so the name match never overrides a choice – the dropdown's new **(match by project name)** entry is the way back: it forgets the project's recorded bank and resolves it again from the name. A project with no bank shows as *(no project bank – shared only)* in the dropdown, where it used to show as "default" – a name, not a bank – beside the real `_shared` row. Every switch is announced in the chat and written to the diagnostic log. And `get_active_project` now carries a warning whenever the active bank is not the open project's – an assistant reading the project sees the mismatch before it builds a request on another client's terminology. Issue #135.
- **Translate and proofread keep separate prompts.** The batch panel wrote whichever mode's dropdown was used into the one stored prompt, so a proofread run replaced the project's recorded translation prompt (and the next translation run, or the translate-segment shortcut, would have used the proofreading prompt). Each mode now has its own stored prompt, globally and per project; the Prompt Manager's "Set as active prompt for this project" sets the one that matches the prompt's category, and the batch dropdown shows the prompt of the mode it is in.
- **The active prompt follows the open project the same way.** The per-project prompt was recorded by snapshotting the global selection when a project was left – so a project that had no prompt of its own kept the previous project's, and then had it recorded as its own at the next switch. A project with no recorded prompt now gets the default, the Batch Translate dropdown shows it at once, and the change is logged. Projects that already have a prompt recorded are unaffected. And with two Studios sharing one settings file, a settings reload in one no longer takes over the other's memory bank: the bank is re-derived from the open project after every reload. Issue #135.
- **`update_segments` can lock and unlock segments.** A locked segment used to need a hand: unlock it in Studio, let the AI write, lock it again. Each update item now takes `locked` (true locks the segment after the write, false unlocks it and leaves it unlocked; sent on its own it changes the lock without writing) and `unlockForWrite` (unlock for this write, lock again afterwards) – so `{id, fp, target, status: "Translated", unlockForWrite: true}` fixes a locked segment in one call. The fingerprint check runs before the lock is touched, a write that fails after the unlock puts the lock back, and every result reports `lockedBefore` and `lockedAfter`. A locked segment without either flag is still refused – now with the way to proceed in the message. Issue #134.
- **When a word cannot be selected because the voice model does not know it, SuperVoice now says so.** "select adsorbent" used to answer *no "add" in the target* – true, and useless, because nobody said "add": the recogniser had matched the sound to the nearest word it knew, and the word asked for is one the model has never contained. The plugin now reads the model's own word list (152,217 words for the English model, 100,006 for the Dutch, straight from the model files, once) and answers *"adsorbent" cannot be heard – not in the voice model's vocabulary*, naming the word when it can tell which one was meant and counting the segment's unhearable words when it cannot. The same check runs on the Dutch source pass. The diagnostic log also records, per segment, how many words the model cannot hear – the number that decides whether voice selection is usable on a given text. Issue #126.

### Changed
- **The SuperVoice documentation is one page.** It was two – "Voice Commands" and a "Dictation" page that had grown to hold selecting words, selecting in the source and selecting by number, none of which is dictation – and a new user could not see the feature as one thing. [docs.supervertaler.com/trados/voice-commands/](https://docs.supervertaler.com/trados/voice-commands/) now opens with what SuperVoice is and what a dictation tool is for, a two-minute video of it in use, and then the pane, the commands, selecting words, selecting by number and the hand-off to your dictation tool in the order you meet them. The beta caution is four lines. The old Dictation address redirects.
- **Voice selection is relabelled beta and ships switched off.** Saying a word only selects it if the voice model knows the word – and measured on a real patent, the small English model does not know 24% of the distinct words in the target, or 34% of the words of seven letters or more, which is the technical vocabulary; the Dutch model, 39% and 47% of the source. The most frequent word in that document was unhearable. That is a property of a small offline model, not a bug, so the feature is presented as what it is: reliable for everyday words, unable to hear most technical ones. `select {phrase}` now ships off, like `select source {phrase}` already did; anyone who has it on keeps it. Selecting by *number* is the planned route to the words the model cannot hear. Issues #126, #128.
- **The Dutch source pass hears only the words after the command.** Fed the whole utterance, a grammar of Dutch source words had nothing for "source select" to be, and the recogniser – which cannot return nothing – mapped those sounds onto the nearest Dutch words it had and handed the matcher three words, two of them never said. It then selected the wrong word and reported success. Vosk now reports where each word ended, and the source pass runs on the audio after the prefix. Issue #127.
- **A selection says what it selected.** The SuperVoice row for a successful selection used to show the command's settings description – "Downloads a voice model for the source language on first use" – in green, so a selection of the wrong word looked exactly like a selection of the right one. It now reads *selected "uitvinding" in the source*, or *2 of 4 – say again for the next*. Issue #129.

### Fixed
- **Licence validation hardened.** Only a reply the plugin fully understood can change stored licence state, and only one confirming the licence is active renews the offline window. A licence reported as no longer active still takes effect immediately, as before. Verified against the live licence API.
- **Saving a term ending in a subscript or superscript digit kept the digit.** Selecting `O₃` and pressing a term shortcut saved `O`: the step that trims a selection to word edges used .NET's letter-or-digit test, which rejects sub- and superscript digits (Unicode category *No*). They are word characters now, and so are the sub/superscript plus and minus of a charge (`⁺`, `⁻`), in the selection trimming and in the matcher alike. And a term is saved in the **Unicode form whichever way the document wrote it**: documents mix `H₂O₂` as Unicode characters with `ClO₃⁻` as a plain 3 and hyphen inside subscript/superscript formatting, and the formatting is markup, not text, so the latter used to be saved as `ClO3-`. The term shortcuts now render subscript/superscript formatting as the equivalent Unicode characters (digits, `+ - =` and parentheses) before saving; the document is not touched. Matching folds both forms to plain characters, so a saved `ClO₃⁻` highlights the formula in either notation. The unpaired-electron dot of a radical (`OH∙`, `SO₄∙⁻`) is part of the word too, in each of the four code points documents use for it, and they are folded to one for matching – TermLens used to split `SO₄∙⁻` at the dot, so the saved term never lined up with the segment. Insertion still inserts characters, not formatting. A term stored **without** a trailing charge or radical dot still matches a formula that has one: making those characters part of the word (above) meant `MnO₄⁻` in a segment stopped finding a termbase entry reading `MnO₄`, which is how every such term saved before this release is spelled. A token whose exact and punctuation-stripped lookups both fail is now retried without its trailing charge or dot, so both spellings resolve and a term that does carry its charge still wins. And trimming that drops a letter, digit or symbol is no longer silent: the quick-add shortcuts ask whether to save the selection as made, the trimmed text, or nothing, and Ctrl+Alt+T opens its editor with the selection as made. Trimming is for edges such as a trailing comma; the characters Unicode has that the trimming does not know about become a question rather than a damaged term.
- **A voice command spoken with the cursor in a Supervertaler text box is now refused with a reason, instead of being typed into it.** "Confirm" with the cursor in the Assistant's chat box sent Ctrl+Enter into the chat box and nothing was said about it; the SuperVoice pane now shows *ignored – put the cursor in the editor*. Only Supervertaler's own text boxes are gated: Studio dispatches its shortcuts application-wide, so "confirm" with the cursor in Studio's Concordance search box confirms the segment, exactly as pressing Ctrl+Enter there does. Issue #129.
- **`list_trados_instances` and the `target` block on every write name the project the editor actually has open.** They could name one project while `get_active_project` named another: both read the open document's project, but the instance handshake went through a copy tracked for per-project settings, updated on a different event and returned first. It reads the same live source now. Issue #134.
- **`add_comment` can target words that contain a non-breaking space.** A plain space in `on` now matches a non-breaking space in the target, so "M8 x 20 mm" finds the range whatever kind of spaces it holds; and `decodeEntities` is accepted, as `update_segments` and `find_and_replace` already accept it, for an `on` or `text` written with `&nbsp;`. Issue #134.
- **The SuperMemory bank dropdown is now wide enough to read the names in it.** The closed box stays narrow – it was deliberately narrowed so that at 150% display scaling the toolbar's last button was not pushed off the end – but the list that drops from it was inheriting that width, and bank names that share a prefix were being cut off at exactly the characters that tell them apart. The list is now sized to its longest name.
- **Terms added or changed in Studio now show up in Supervertaler Workbench's term search.** The shared database's full-text index – the one Workbench's search reads – was maintained by nobody: this plugin never touched it, and Workbench itself rebuilds it once during a migration and never again. So every term added afterwards, from any product, was missing from that search, and every deleted term still matched. Three triggers on the terms table now keep the index current for every writer at once – this plugin's sixteen write paths, Workbench's own, Supervertaler for memoQ's – installed the first time this build opens a database for writing, with a one-time rebuild that repairs the index as it stands (about a tenth of a second per 36,000 terms). Only affects people who search terms in Workbench; Trados itself never read that index. Issue #133.
- **A termbase database whose full-text index could not be created now says so in the diagnostic log.** This plugin never queries that index, so the failure was swallowed as "non-critical" – but Supervertaler Workbench searches through it, and a SQLite build without the FTS5 module produces a perfectly valid file whose search finds nothing, in a different product, with no trace of why. Still non-fatal; no longer silent. Found while the three products' termbase handling was being lined up (#133).

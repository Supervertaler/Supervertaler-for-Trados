## Changelog

### Added
- **SuperVoice: select words by voice, in the target or the source, and hand off to your dictation tool.** Voice commands could drive Studio; they could not touch the text. Now **"select the duty cycle"** selects those words in the target, **"select source nachtzichttoestel"** selects in the source, **"delete that"** deletes, **"undo that"** (or Dragon's **"scratch that"**) undoes, and **"dictate"** / **"stop now"** hand the microphone to a dictation tool such as Wispr Flow and take it back – with the stop phrase mapped to a marker the plugin removes. While a segment is open its words join the recogniser's vocabulary, so it can hear what is in front of you; a "select" utterance is then heard a second time against the segment's words alone, which stopped our own command words stealing sounds ("term eight" had made the article *a* unsayable). Dropped words are tolerated ("comprises most" still finds *comprises at most*), a word inside another word is never selected ("the" no longer lands inside *further*), hyphenated compounds work spoken as their parts, and **saying a phrase again steps to its next occurrence** – or, for a single word, through every word it could mean – with the strip saying **2 of 4**. Source selection needs a voice model for the source language, downloaded on first use (Dutch to start), and is read-only: deleting or dictating over source text is refused. Long Dutch and German compounds the model has never seen are reached through their parts, because no model of any size contains them – measured. Both `dictate` and `select source` ship switched off. See the new **Dictation** page in the docs. Issues #125, #127.
- **A `"stop now"` command that only stops.** A single toggle with "stop now" as an alias started dictation when said at the wrong moment, and every command after that was silently swallowed. Start and stop are two commands now; saying either twice does nothing.
- **The strip says what happened, not just what was said.** A refusal ("the" is inside another word – say more words), an ambiguity (2 of 4 – say again for the next), a miss (did not catch that word – try one next to it) all reach the status strip instead of being overwritten by the command echo, which is why none of them was seen in the first day's testing.
- **`add_comment` can now put a Trados comment on a range of words inside the target, not only on the whole segment.** Give `on: "the words"` (and `occurrence` when they repeat) and the note lands exactly where it belongs – the same as the editor's Add Comment on a selection. The caller names the words rather than character positions, because an AI reasons in words and a position is wrong the moment anything else touches the segment; it is the convention `find_and_replace` already uses. A range that would cut across an inline tag is refused with a reason, as the editor refuses the same selection. Without `on` nothing changes. Issue #132.
- **`get_comments` now says where each comment sits**: which side (`source`/`target`), whether it covers the whole segment or a range (`scope`), and for a range the exact words (`on`). Until now a comment on three words and a comment on the whole segment came back indistinguishable. Issue #132.
- **Batch Translate now searches your translation memories, so a fuzzy match can be sent – together with the source it was made for.** #110 could only send 100% matches, because Studio records how close a match is but not the source it was made for, and a fuzzy sent as a bare target is a translation of a sentence the model cannot read. Supervertaler now asks the memories directly, and a search returns both sides. A match reaches the model as the memory's own source, the approved translation and the percentage, under an instruction to compare the two word by word and carry the translation across only as far as they agree – a reference it may ignore, not an authority. **A target is never sent without its source.** Because it asks the memory rather than reading what pre-translation left behind, it also works on **empty segments**, which is the case that matters most: batch-translating untranslated text with your closest approved wording beside it. **Lowest TM match to send** in AI Settings sets the floor, 70% by default – where Studio's own fuzzy band starts; set it to 100 for exact matches only. The Batch Operations checkbox is now **Send TM matches to the AI** and still turns the whole thing off. Preview prompt searches too, so what it shows is what gets sent. Measured on a 3.5 GB `.sdltm`: 238 ms for twenty segments, cold, with repeated sentences looked up once. Issue #116.
- **One click sets Google Antigravity up to use the tools instead of rummaging through your project folder.** Antigravity connects like any other MCP app, but its agent also has a shell and a file browser – and left to itself it answers Trados questions by reading `projects.xml` and the `.sdlxliff` on disk, both of which are stale by definition, because Studio holds the document in memory. On one 675-segment project that was eight minutes, thirteen shell commands and no answer; the same question with the tools named took fourteen seconds. A short instruction file fixes it completely, and **Supervertaler Settings → AI Settings → Connect AI assistant… → Install Antigravity skill** now writes it for you. The file tells the agent to load your recorded decisions first, then run the checking tools, then read the bilingual text, and not to write scripts to do any of it – and it says never to edit anything in the project's `Studio` folder, because segment changes belong in `update_segments`. Asking you to create `%UserProfile%\.gemini\config\skills\supervertaler-trados\SKILL.md` by hand meant a folder you have never opened, a file Notepad saves as `SKILL.md.txt`, and YAML that breaks on a stray space. It ships with the plugin rather than living in the documentation so that it stays current: it names specific tools and rules, and a copy pasted once would slowly start describing a toolset that no longer matches. If you have edited your own copy, it is backed up before being replaced. The Gemini CLI reads the same folder, so it is covered by the same click. Issue #117.
- **Batch Translate now sends the 100% translation memory match Studio already put in a segment, and a checkbox turns it off.** It sent nothing at all from your TMs before: a run over pre-translated segments rewrote what the memory had supplied without the model ever seeing it. Any segment in scope whose target came from a TM as an exact match now goes to the model with that translation, under an instruction to keep it. **Only exact matches are ever sent.** Studio records how close a match is but not the source it was made for, so a fuzzy could only be offered as a translation of a sentence the model cannot read - unable to tell which words differ, and most misleading exactly where a memory has been padded with near-misses to manufacture matches. At 100% the match's source is the segment's source, so nothing is hidden. **Send 100% TM matches to the AI** on the Batch Operations tab turns the whole thing off for a job whose memory you do not trust. Issue #110; sending fuzzies safely needs the memory searched for its source text, which is #116.
- **Translations written through the MCP server are now checked against the segment they were actually made for.** `get_segments` gives every segment a short fingerprint of its source, and `update_segments` refuses to write into a segment whose source no longer matches the fingerprint it was handed. Until now a translation was addressed by position alone, and a position is not an identity. If the assistant lost its place partway through a long batch and returned two hundred perfectly good translations against ids shifted by one; if you picked a conversation back up and applied its translations to a document that was no longer the one open; or if a segment was split or the file re-imported while a batch ran – every write succeeded, and the reply read “applied: 200, failed: 0” over a document that was quietly wrong. Those segments are now refused one by one, each with the reason, while the rest of the batch goes through untouched, and the reply tells the assistant to re-read the document rather than retry without the check. Segments sent without a fingerprint are written exactly as before, so nothing that worked yesterday stops working. When everything is in order you will never see it.

### Changed
- **The document context now carries the document's own list numbering, not just the segments being translated.** Structure markers (#109) reached the numbered segment list but not the copy of the document sent as context, so the claims of a patent arrived numbered in one half of the request and unnumbered in the other. The numbering is what says a paragraph IS claim 2 – without it “volgens conclusie 1” has nothing to resolve against, and the model cannot see that a run of paragraphs is a numbered set at all. Both halves are now built from the same resolved map, so they cannot disagree. It costs about 210 characters in a 76,000-character context on a real patent: 35 markers across 793 paragraphs. **AutoPrompt sees them too**, with a paragraph of its own explaining what they are – it is asked to read the document and write instructions for translating it, so it should see the structure the translating model will see, and it may now write guidance on using it. Markers travel only where something explaining them travels: Chat, the MCP `get_prompt_context` tool and Batch Proofread are unchanged, the last because it has no structure-context support yet. Issue #122.
- **API keys are now encrypted at rest.** Every provider key was stored as plain text in `settings.json`. It is now encrypted with Windows DPAPI, bound to the Windows account that entered it, so a settings file carried anywhere else – synced to a cloud folder, zipped into a support request, left on a shared or disposed machine – carries nothing usable. Nothing changes in the dialog: you paste the key into the same field and it is encrypted on save. An existing file is converted once, on the first start after updating, and the old plain-text values are removed. What DPAPI does not do is protect a key from a program running under your own Windows account – nothing that stores a secret locally does – so this is about the file moving, which is how keys actually leak. Because the encryption is tied to the account and the machine, a settings file restored from a backup or moved to a new PC will not decrypt: the AI Settings tab says so and asks you to paste the key in again, instead of showing an empty field that would surface later as an authentication error from the provider. The GroupShare server password has been encrypted this way since #35; the helper now lives in the shared core, so Supervertaler for memoQ uses the same one. Issue #115.
- **Two chats in the same AI app can no longer send a translation to the wrong Studio.** With Trados Studio 2024 and 2026 open side by side, the "which Studio am I working in" choice is one setting shared by every chat on the machine – the MCP protocol gives the server no way to tell one conversation from another – so two chats that each picked a different Studio were both pointed at whichever was chosen last, and a write into the wrong project would not be refused, because *a* choice existed. Two changes close that. Every Supervertaler tool now takes an optional `instance` argument – `"2024"`, `"2026"`, or part of the project name – resolved against the Studios actually running, on **reads as well as writes**: a chat that passes its own Studio on every call reaches that one or is refused by name, whatever another chat has since selected, and never needs `select_trados_instance` at all. That last point is the whole fix – `select_trados_instance` sets one selection shared by every chat, so two chats that each used it kept overwriting each other's choice; the per-call `instance` gives each chat its own answer and sidesteps the shared selection entirely. Every write, and every call that named an instance, also reports the Studio and project it went to, so a wrong target shows in the reply rather than in the wrong document later. The MCP server is a separate download; update it (reinstall the `.mcpb`, or replace the exe) to get this. Issue #121.
- **The dockable panels have their own icons instead of Studio's generic one.** TermLens, TermPicker, SuperSearch and the Supervertaler Assistant all declared the icon `TermLensIcon`, and no such resource existed - so Studio looked it up, found nothing, and drew its fallback on all four tabs. Each now has a glyph of its own in the Supervertaler blue: term chips for TermLens, a list for TermPicker, a magnifier for SuperSearch and a speech bubble for the Assistant. They show on the **View** ribbon, where you pick a pane to open. The icons are `.ico` files carried as `System.Drawing.Icon`, which is what `AbstractViewPart.Icon` is declared as - a bundle holding `Bitmap`s instead reads back perfectly outside Studio and then takes the editor down with it. The resource bundle is now built by `tools/make_plugin_resources.ps1` rather than compiled from `PluginResources.resx`: an SDK-style project cannot compile images into a .resx without the preserialized resource format, and that format needs `System.Resources.Extensions.dll` loadable at the moment Studio reads the resource - during plugin discovery, possibly before our own assembly resolver exists. A miss there would cost the whole plugin rather than an icon, so the script writes the classic format under Windows PowerShell instead.
- **The two AI Settings sections that hold the context switches are now called Context layers.** Supervertaler sends the AI ten layers of context beyond the sentence being translated – project and file, the current segment, the segments around it, the whole document, TM matches, termbase terms, SuperMemory, the document’s list numbering, descriptions of its figures, and anything you attach by hand – and those switches are where you turn them on and off. The docs page that listed them, Context Awareness, is now [Context layers](https://docs.supervertaler.com/trados/context-layers/) and covers all ten; the old URL redirects.
- **The image feature has a name: FigureLens.** It sits beside TermLens, which shows the terms in a segment, and does the same job for the pictures: it is the panel that gets the images out of your documents and gives the AI a description of each. The Batch Operations link, which read “▣ Images…”, now reads **FigureLens…** – the little framed square in front of it was decoration nobody could decode. Supervertaler for memoQ uses the same name for the same feature.
- **The reference-numbers report now names the number the sequence skips, and the button says what it is in plain words.** A patent that cites (1) to (4), (6) and (7) is told outright that (5) is cited nowhere – usually a part renumbered or dropped while the document was drafted, and invisible in a list of what *is* cited, because the reader has to notice an absence. Gaps are reported only where they mean something: a document citing (1) and (250) has 248 “missing” numbers and no defect. The link, which read “№ Reference numbers in the text”, is now **(12) Reference numbers** – the old numero sign rendered as an odd N with a small o, and the example in front of the words shows what is meant without a second word for “number”.
- **FigureLens lists your documents in two columns.** Name in one, what was found in it in the other, so on a project of several files the names line up under each other instead of the eye hunting for where each one ends. Documents with images come first, then those with none in grey, then any that could not be read in red, with the reason beside it. Brought over from Supervertaler for memoQ, where the same change was made first.
- **The image reader no longer depends on the OpenXml library.** It reads the Word package directly, the way the list-numbering reader does, and was checked against the old reader document by document, image by image, byte for byte. Two things it now does that the old one did not: a document that is open in Word at the same time is still read (Word holds a write lock, and the old reader reported no images for a file that had several), and images in the fallback copy Word keeps of some shapes are no longer counted twice. The same reader is shared with Supervertaler for memoQ, as are the figure analysis and the figures.md writer; and the question put to the AI about each image no longer assumes a patent drawing.
- **The figure pipeline is one panel, FigureLens, instead of five links.** Batch Operations used to list Document images, Reference images folder, Extract images to folder, Write figures.md and Analyse images as five peer links, in build order, which read as five unrelated choices when four of them are stages of one job. **FigureLens…** now opens a panel that shows the state and implies the order: the reference images folder with a Browse button, what the project’s Word documents contain (images found, how many carry a figure label, and how the labels were established), the three stages as buttons with their cost beside each – Extract (free), Analyse with AI (one request per image, the provider named), Write figures.md (free, text only) – and a line saying when figures.md was last written, how many figures it holds and whether the AI has looked at them yet. Buttons that cannot run yet say why. The Document images report is a link at the bottom. Reference numerals stays a separate link, because it is a text check, not part of the pipeline. Also fixed: the confirmation before an AI analysis replaced figures.md showed a stray `''' + N + N + '''` where its line breaks should have been. Issue #84.
- **The last connections to Supervertaler Workbench are gone.** The plugin no longer offers anything that needs Workbench installed: the Shared TM Bridge translation provider (“Supervertaler TM Bridge” in Studio’s provider list) and its MCP tool `search_tm`, which searched only those bridged TMs; the “QuickLauncher prompts go to” dropdown in AI Settings, which had had one entry since the Workbench Chat route was retired; the hidden `sidekickBridgeEnabled` switch, since the localhost bridge now exists for the MCP server and starts whenever you have Assistant access; and the `[Workbench]` app tag on prompts. Translations inserted through the MCP server are now stamped “Supervertaler” as their origin instead of “Supervertaler Workbench”. The first-run folder dialog, tooltips and messages now talk about Supervertaler for memoQ and Sidekick, which share the same data folder. Studio TMs are still searched with `search_studio_tm`, which was always the right tool for “how did I translate this before?”. Issues #88, #78.
- **List numbering as structure context is now on for everyone, and the checkbox is gone.** 18.20.188 shipped it opt-in so the first real runs could be checked. They were: across the model line-up tried so far no sentinel reached a target, the strip never had to fire, and the phantom “steps a. to f. are unlettered” flag that started it is gone. So Batch Translate, Translate Segment, Clipboard Mode and SuperBench now send the markers without asking. A hidden `structureContext` switch stays in `settings.json` for support cases.

### Fixed
- **Adding, editing or deleting a comment through the MCP server no longer turns a Translated segment into a Draft.** Writing through Studio's edit path marks the segment as edited, which is right for a translation change and wrong for a review note; the segment's confirmation level is now put back afterwards, the way `update_segments` already does. Found on the first live check of the new range comments – and the first fix missed, because it restored only when the level read back as changed, which at that moment it never has. Issue #132.
- **The locked glossary in a generated prompt is now checked against the termbase it was built from, and put back where it drifted.** AutoPrompt hands the generating model your termbase and asks it to reproduce every row in a section it marks MANDATORY and LOCKED. It mostly does. On a real 280-term run it dropped one row and rewrote two targets into variants – *to grind* became *grinding / ground*, *upper side* became *upper side / top side* – in a table the same prompt had declared locked, three paragraphs below its own rule that such formulations “silently reopen the very choice the lock was meant to close”. About 1% of rows, invisibly, in the one section whose entire value is being exact. The saved prompt now has every supplied term forced back to the termbase wording, any dropped term restored, and a note in the chat saying what was repaired. Rows the model added itself are left alone – with no AI-enabled termbase, deriving a glossary from the source is the whole point of AutoPrompt – and so is its formatting: it italicised a species name and added a full stop, which is correct convention and not drift. Only a difference in **words** is repaired. Issue #124.
- **Preview prompt is readable now: lines wrap, and it says which request you are looking at.** Long lines ran off the right edge – and a prompt is mostly long paragraphs – so reading one meant scrolling sideways, line by line. The fact that a large scope is split into several requests, and that this is the first of them, was a note at the very bottom: on an 880-segment document that is 90,000 characters below the top, where nobody reads it. It now leads the banner, with how many requests there are and how many segments this one carries. Both together are why a structure marker or a segment can look missing when it is simply past the right edge, or in request 12.
- **The “Send TM matches to the AI” checkbox now remembers being switched off.** It was never written to `settings.json`: the setting carried no serialisation attribute, and the serialiser writes only marked members, so it silently returned to on at every Studio restart – since it shipped in 18.20.189. A job whose memory you had decided not to trust would start sending its matches again the next morning. Issue #116.
- **A Claude reply that was cut short is no longer handed back as if it were complete.** Claude calls – both the single-prompt path Batch Translate uses and the chat path behind the Assistant and AutoPrompt – are now streamed and read as the model generates, rather than held as one silent request until the whole reply exists. Three things follow. A reply whose stream ends without the end-of-message event is reported as cut off, with how far it got and that running it again may succeed, instead of arriving as a “successful” reply missing its last third. A stream that stalls is abandoned after the timeout rather than hanging forever, which on .NET Framework it otherwise would. And the chat path now records token usage and the model’s own stop reason, which it never did. The prompt log gains a `finishReason` field carrying that stop reason in the provider’s own word – “end_turn”, “max_tokens”, “length” – so a cut-short reply can be told from a finished one from the log alone. Issue #119.
- **AutoPrompt no longer sends the whole document, your memory bank and the project context twice.** Generating a prompt sent two independently built context blocks in one request: the meta-prompt, which carries its own copy of the document, the termbase, previous translations and SuperMemory – and, attached alongside it, the Assistant's ordinary chat system prompt, carrying a second copy of the document, SuperMemory and the project context, and opening by telling the model it was a translation assistant where the meta-prompt had just told it it was a prompt engineering specialist. On a real 451-segment run that second block was 126,432 characters, about 31,600 tokens, of which 70 % appeared word for word in the first – roughly **30 % of the request, paid for and reasoned over twice**. Prompt generation now sends no system prompt at all: the meta-prompt was always self-contained. Beyond the cost and the wait, this is also the cheapest way to reduce the pressure behind the truncation fixed above, because the size of the input drives how much a reasoning model thinks, and that thinking comes out of the same budget as the prompt it is writing. Issue #120.
- **AutoPrompt on Claude Fable 5.1 no longer runs out of room for the prompt.** Five runs in a row came back two-thirds written and were refused by the check above, and the new `finishReason` field said why: `max_tokens`, with the full 32,768-token budget spent. Fable reasons before it writes, and on a large input – a whole application plus the memory bank, the termbase and the project’s existing translations, 137,000 tokens in – it spent some 27,000 of those tokens thinking and about 5,000 on the prompt, which needs 13,000. It could never fit; it only ever looked like a time limit because 32,768 tokens at that model’s pace is about 400 seconds, and the old code logged only estimates of the visible text. Two changes, applied only to prompt generation and only on models with adaptive thinking (the Claude 5 family): the request now asks for **medium** reasoning effort instead of the default high, and the output ceiling is **65,536** tokens, so the prompt fits even when the model reasons hard anyway. Nothing changes for ordinary chat. The “prompt not saved” dialog now states the stop reason as a fact – *the model reached its output-token limit* – instead of offering it as one of three guesses. Issue #119.
- **Preview prompt showed the Clipboard Mode prompt even when Clipboard Mode was off.** It called the clipboard formatter unconditionally, so for an ordinary API batch run it rendered a prompt that was never sent: a different format, without the batch instructions, and - once Batch Translate began sending translation-memory matches - without those either. The docs have always said Preview shows exactly what would be sent, and for the API path it did not. It now mirrors Batch Translate: the same system prompt, and the same numbered segment list built by the same function, so a preview and a run cannot drift apart. Where the scope is longer than one request, the preview shows the first request and says how many there would be. Clipboard Mode previews are unchanged.
- **A truncated AutoPrompt result can no longer be saved as a prompt.** A generated prompt was cut off mid-file - the last line was half a glossary row - and the missing third of the glossary, the output-format section and the previous-translations section went unnoticed. It was used to translate an entire document, and the prompt's own body referred the model to a section number the file did not contain. Two things now stop that. A response that begins a prompt and never closes it is refused outright: previously the extractor returned nothing and the raw, truncated text was saved as though finished. And a prompt that does parse is checked before it reaches the library - it must have an OUTPUT FORMAT section, its last heading must have a body under it, its section numbering must be contiguous, every "section N" it cites must exist, and no table row may stop without closing its last cell while its neighbours close theirs. Any failure refuses the save and says which check failed; nothing partial is ever written. Checked against the 29 prompts already in the library: 27 pass untouched, the known bad one is caught twice over, and 10 of 10 arbitrary truncations of a good prompt are refused. Issue #112.
- **Vector drawings are described too, instead of coming back “not a format a vision model accepts”.** A drawing placed from CAD or a draughtsman’s tool is usually a metafile (EMF or WMF), which no AI can read – so on exactly the documents the feature exists for, every figure failed after being extracted perfectly well. They are now rendered to PNG as they are extracted, on a white background and large enough for the thin lines and the reference signs to survive, and the AI reads them like any other image. One that will not render is still written out as it was, and its row says to open it and save it as PNG. A folder holding such files is also no longer reported as empty.
- **A project with several documents holding images described only the last of them, and one document's images could overwrite another's.** *Describe images with AI* wrote a figures.md whose table covered the last document alone, while the count above it included every figure; and every document's images were extracted into the same folder, so a second document's `Figure 01.png` replaced the first's and the first was then described from the wrong file. Each document now gets its own folder and its own table, and each row is tied to the image it came from rather than to a position in a list, so an image that cannot be written no longer shifts every row after it. Found by the Supervertaler for memoQ side while building the same panel there; both products had it.
